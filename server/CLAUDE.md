# server/: the one authoritative backend (READ BEFORE EDITING)

- `sessionStore.ts`: `applyAction(session, action, nowMs, patients)` is **synchronous and pure given its inputs**. Never add `await`, timers or `Date.now()` inside it; time is injected. This is what makes first-write-wins race-free (Node is single-threaded). Every action has a UUID `clientEventId`; a repeated `device:clientEventId` pair (per session) returns the original result unchanged. The replay cache stores results without the state snapshot, capped at 200 ids, and sessions are an LRU capped at 50 (`getOrCreateSession` evicts the oldest session with no connected socket).
- First-write-wins: a second `LOG_MED` for an already-given med returns `{ok:false, conflict:true, message:"Already given {time} via {device}"}` and changes nothing. Undo works only within 10,000 ms of server `acceptedAtMs`.
- `index.ts`: Express + `ws`. WS path `/ws` (session sync) is claimed manually via `noServer`; `/ws/stt` (Deepgram proxy, in `api.ts`) claims its own path. Never create a `WebSocketServer({server, path})` (ws rejects the other path with 400). It serves `dist/` whenever it exists (no NODE_ENV needed, Windows-safe) and binds `0.0.0.0`.
- Identity: `device` comes from the socket's connect query, never the frame body. Director-only actions (RESET_SESSION, SET_CLOCK_OFFSET, SIM_*, START_SHIFT with baseMin) need `device=director` or `director=1` (plus `key` when env `DIRECTOR_KEY` is set); the check is in `index.ts`, the shape bounds are in `validateAction`.
- Upgrade handlers must never throw: parse the URL in try/catch and `socket.destroy()` unknown or malformed paths. `/ws/stt` is capped at 4 sockets. A 15s server ping terminates sockets that miss two pongs. `installCrashGuards()` logs uncaughtException/unhandledRejection and keeps serving.
- Timers and fan-out live in `index.ts`, never in `applyAction`: the 5s doctor reply after `WOUND_SEND` (`drReplyDelayMs` option for tests, cleared on `RESET_SESSION` and `close()`), `SIM_DR_REPLY` firing it at once, presence broadcast (`{t:'presence'}` on connect/disconnect), ping/pong, and a `result` for EVERY action to the dispatcher. Wound status, `eventSeq` (monotonic, survives reset) and the assignment check (`nurse.assignedPatientIds`) are in `sessionStore.ts`; contract in `docs/FRD-v2.2.md` section 4.
- `api.ts` / `assessWound.ts`: `POST /api/assess-wound` must return within ~3.5s with the fallback answer on timeout, error, bad JSON or missing `GEMINI_API_KEY`. Never throw out of a route. Model id comes from `GEMINI_MODEL` (default `gemini-3.5-flash-lite`, see `docs/RESEARCH.md`); never hardcode `gemini-2.5-flash`.
- Treat all input as untrusted: validate WS/REST shape and size, never trust `device` or ids from the client, never log secrets or PHI-looking text. Keys come from env var names only (`GEMINI_API_KEY`, `DEEPGRAM_API_KEY`).
- Wave 2A: `LOG_MED` not due within 30 min needs `earlyConfirmed` (`needsConfirm` result). `TELEMETRY_SAMPLE` is bounded (20 per metric) and, like `SET_GLASSES_VIEW`, never an event; `GET /api/telemetry?session=`. `state.feed` (med and wound events with a verification `chain`) is separate from `events[]`, which stays the command bus the glasses replay (it keeps `SIM_*`). Wound assessment with no photo returns `source:'unavailable'` (never a finding); `WOUND_SEND` of an unavailable capture is refused. `SIM_ADD_CONFLICT_ORDER` fills `extraOrders`. `RESET_SESSION` must delete every optional key (`Object.assign` does not).
- Safety and handoff protocol (details in FRD section 4): `LOG_MED` on an allergy conflict needs `allergyConfirmed` (`needsConfirm`); `ALLERGY_ACK` fills `allergyAcks[]`. Handoff packets (`state.handoffs`, built by `shared/handoff.ts`, no LLM) move through `HANDOFF_OFFER` / `HANDOFF_READBACK` / `HANDOFF_ACCEPT`; the connection `instance` is stamped by `index.ts` from the connect query and never read from a frame body (`validateAction` drops it); readback and accept fail closed without a different instance. `SIM_*` payloads ride on bus events as `detail`. `RESET_SESSION` must delete `allergyAcks` and `handoffs` too.
- All data is synthetic (`data/patients.json`). Run `npm run audit-pii` after touching data.

Verify: `npm run typecheck && npm test`. A change to `applyAction` needs a test that you have seen fail first (mutation check), see `sessionStore.test.ts`.
