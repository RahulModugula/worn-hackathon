Sync correctness

Four rules, each with a failing test.

First write wins

Exactly one given per medication. A second device is told who won.

10 s cross-device undo

Either device can undo, only inside 10,000 ms.

Idempotent events

A replayed clientEventId never changes state.

Offline outbox

Actions queue in localStorage and flush once on reconnect.

Applying an action is synchronous on the server (no awaits inside), so two actions can never interleave.

Proof, not assertion

We tried to break it.

  • 20,000 seeded action sequences, invariants checked after every step.
  • Mutation checks: undo window +1 ms, first-write-wins off, reset leaving state behind. Each failed within a few sequences.
  • 200 sockets racing one dose: exactly one winner.

Replay any failure with STRESS_SEED=n STRESS_RUNS=1.

Display law

640x480, black is see-through.

  • Clear zone x120-520 / y90-290 is always empty.
  • Bottom card y300-440, 528 px inner, text 18 px or larger.
  • Every line is nowrap with ellipsis; copy is verbatim from the spec.
  • Scanner reads only the centre 480x480 of 1280x720, 4 FPS.

Legacy WebView

Built for Chromium 69.

  • Android 9 WebView, factory version unknown, so we build for 69 and guard it.
  • check-legacy fails the build on syntax, CSS or APIs 69 lacks.
  • Hand-written polyfills, no core-js. Glasses route never loads phone code.
