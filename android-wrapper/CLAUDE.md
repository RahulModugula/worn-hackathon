# android-wrapper/: WebView shell that runs our /glasses page on the M6

- Purpose: a fullscreen black WebView that loads `http://localhost:3001/glasses` (through `adb reverse`) or any `--url`. It exposes `window.__M6_BRIDGE__`, logs every key event under the logcat tag `BG_KEYS`, and forwards Enter (tap) / Escape (long-press) to the page. The page maps the `glasskey` event (`{code, action, scanCode, source}`, no `key`): DPAD_CENTER (23) or ENTER (66) action `down` is a tap, BACK held (`code 4`, `long-press`) is a long press; the DOM Enter/Escape twin within 300 ms is ignored.
- Facts NOT yet verified on real glasses: ring/touchpad key codes, WebView camera/mic, WebView version. Do not hardcode guesses; record measurements in `docs/decisions/topology.md`.
- Prebuilt APK: `prebuilt/bedside-wrapper-debug.apk` (committed on purpose so teammates need no Android Studio). If you change Kotlin, rebuild with `./gradlew assembleDebug` (JDK 17, Android SDK platform 36 + build-tools 36), copy the APK to `prebuilt/`, and check `aapt2 dump badging` shows package `com.bedsideglance.wrapper`, minSdk 28.
- Security: the page can call the bridge, so only load trusted URLs (our server). `MainActivity.isAllowedHost` allows localhost, 127.0.0.1, private LAN addresses (10.x, 172.16-31.x, 192.168.x.x) and *.onrender.com: camera/mic permission requests, page navigation (`shouldOverrideUrlLoading`) and the `url` intent extra are all checked against it. WebView remote debugging is on only when the app is debuggable (the committed APK is the debug build). Motion events reach the page at most once per 100 ms. The bridge has only log/getInfo, so the page uses getUserMedia for the camera. Never put secrets in the APK or intent extras.
- Never copy anything from `kit/` (confidential) into this folder.
- `local.properties` is machine-specific and gitignored.
